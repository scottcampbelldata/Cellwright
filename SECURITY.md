# Security and privacy

The native scanner reads originals, never invokes Office or executes macros, never refreshes connections and makes no network requests. Reports embed resources. Each workbook is isolated in a timed process: default two workers, 128 MiB input, 16 MiB per part/stream, 256 MiB aggregate retained ZIP parts, 10,000 entries, CFB depth 32, XML depth 128/one million events and 64 MiB response. Oversized non-VBA ZIP parts are skipped without decompression; their names and declared sizes are reported with MF060 and unknown coverage, while bounded VBA is still inspected. Oversized VBA, encrypted entries, excessive entry counts and retained aggregate-size violations still reject the workbook. Reads/decompression are bounded; DTDs are rejected. These controls are not an OS memory sandbox or malware-analysis certification.

VBA editor protection is metadata, not encryption. `--skip-protected` omits protected/unknown-protection VBA. Password-to-open encryption is detected without decryption. `--no-source` removes VBA/M/designer data from reports; CSV never contains source. Metadata includes paths, names, owner identifiers, hashes/references/findings. Dashboard scans default to source-free reports. Extraction/conversion outputs contain source and can be confidential.

HTML escapes workbook content and uses CSP. CSV neutralises formula cells. Generated filenames are sanitised; output directories must be new/empty. Designer snapshots have a 16 MiB aggregate bound. Cache/source flags are heuristics; p-code is not decompiled and signatures are not verified.

Conversion disables automatic macros/link updates, writes new files and preserves source/diffs. ODS candidates remove other imported Basic libraries, document/sheet event bindings and imported form-control callbacks. Basic targets reattach only a single push-button action to an unambiguous public parameterless Sub in a standard module without TODOs, using a generated document-local wrapper. ActiveX or incomplete control coverage prevents automatic rebinding. Wrappers are installed without invocation; review every binding before use. Other embedded controls and shape behavior remain manual. Unsupported Basic code remains intact with TODOs, so candidates can contain unsafe original routines.

Capture/verify/run-python require explicit execution consent for **trusted code**. Office/Python execution is not sandboxed and can access files, network and services. Use a disposable VM for untrusted code. The harness invokes the named routine, suppresses open events, uses private LibreOffice profiles, bounds runtime/cell captures, closes its own Office instances and checks the original hash. It cannot prevent external side effects. Passing cases cover only observed inputs/cells.

M execution is allowlisted, without arbitrary eval. File sources must resolve within `--data-root` and bounded size; network providers are unsupported. General M semantics/resource isolation are incomplete. openpyxl cannot calculate formulas.

The dashboard binds to loopback, validates exact `127.0.0.1`/`localhost` hosts and matching origins, uses a random session token, HttpOnly same-site download cookie, CSP, parameterised SQLite, bounded JSON and resolved artifact paths. The session token is available from the dashboard page: it prevents cross-origin browser requests, but does not authenticate local programs. Macro verification is disabled unless the owner starts the server with `--allow-execution`; each request still requires case consent. With that flag, any local process able to reach the server can obtain the token and request execution with the server's privileges. Keep this flag off during routine inventory/conversion. It has no remote/multi-user authentication. Do not expose the port publicly. Schedules run only with the server; use distinct data directories per instance. Filesystem users can read stored results.

Local binaries are unsigned; SBOM/hash manifests are not attestations. No independent security audit or production signing/release has occurred.

Report suspected vulnerabilities through [GitHub private vulnerability reporting for scottcampbelldata/Cellwright](https://github.com/scottcampbelldata/Cellwright/security/advisories/new). Include the affected version, reproduction steps and a minimal sanitized example. Reports are private to the repository's security maintainers until coordinated disclosure. Do not post confidential workbooks or source in public issues.
